### 1. Review Collector + Tools framework (`3af259d`)

**Goal:** Per-business review-request tool. Owner sends customer an email → customer taps stars → 4-5★ routes to Google review URL, 1-3★ routes to private feedback form → owner gets the private feedback by email. Compliance: Google link always visible (no review gating).

**Schema** (`src/lib/schema.ts`, migrations `0016`/`0017`/`0018`):
- `business_tool` — per-business grants (`free`/`gifted`/`trial`/`paid`, optional `expires_at`, `granted_by` audit)
- `business_review_settings` — 1:1 sidecar (Google URL, brand color, logo, sender name/sig, notification email)
- `review_request` — lifecycle (`sent`/`opened`/`submitted`/`expired`) + `rating` + `google_clicked_at`
- `review_feedback` — private 1-3★ messages

**Access helper** (`src/lib/auth/tool-access.ts`): `hasToolAccess(businessId, toolSlug)` honoring expiry; `getOwnedBusinessesForUser(userId)`; `getToolGrantsForBusiness(businessId)`.

**Service** (`src/lib/services/review-collector.ts`): token gen (32-char base64url via `crypto.randomBytes(24)`), CRUD, stats aggregation in one SQL pass.

**Rate limiter** (`src/lib/utils/rate-limit.ts`): in-memory token-bucket. Public `/r/*/rate` capped 10/min/IP+token, `/r/*/feedback` capped 5/min. Swap for Upstash if we ever scale past one Vercel instance.

**Email templates** (Mailgun, HTML-string style matching existing claim templates):
- `src/lib/email/templates/review-request.ts` (customer)
- `src/lib/email/templates/review-feedback-notification.ts` (owner)

**Surfaces:**
- Owner: `/ai-tools/review-collector` (home), `/send`, `/feedback`, `/settings`
- Public: `/r/[slug]/[token]` (star tap), `/feedback`, `/thanks`, `/go` (tracked Google redirect)
- Admin: `/admin/tools` — combobox business search + active-grant table + revoke

**Quick Access reordering:** Both `/ai-tools` and `/dashboard` now surface granted per-business tools ahead of generic credit-model tools so freshly-granted tools aren't buried below the fold.

**AITool type extension:** `accessModel?: "credits" | "per-business"` on `src/lib/types/business.ts`. `credits` is the default when omitted.

### 2. Submitter ownership fixes (`ab6357e`)

A user who *submits* a business gets `submittedById` set; `ownerId` only gets set when a *claim* flows through. The edit page and PATCH API only checked `ownerId`, so a submitted-then-approved listing 404'd at `/dashboard/my-businesses/[id]/edit`.

Fixed three files:
- `src/app/dashboard/my-businesses/[id]/edit/page.tsx` — query matches dashboard logic (owner OR submitter)
- `src/app/api/admin/businesses/[id]/route.ts` — `canAccessBusiness` accepts submitter too
- `src/app/api/admin/businesses/[id]/status/route.ts` — when admin transitions to `published` and there's a submitter but no owner, stamp `ownerId = submittedById` and set `claimedAt`

Backfilled 3 already-approved listings via one-off Node script (not via psql — psql isn't installed on the user's machine; their `$POSTGRES_URL` also doesn't expand in shell before `pnpm dotenv` loads it).

### Auth gotcha worth remembering
The user hit "Failed to sign in with Google" on localhost. Root cause: `NEXT_PUBLIC_APP_URL` in `.env.local` was set to `https://freddybeach.com`, and `src/lib/auth-client.ts:7` uses that as `baseURL`. Means localhost OAuth callbacks were going to prod. Fix: set both `NEXT_PUBLIC_APP_URL=http://localhost:3000` AND `BETTER_AUTH_URL=http://localhost:3000` in `.env.local`. Vercel envs override for prod.
